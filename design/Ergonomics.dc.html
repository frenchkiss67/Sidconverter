Pick the file once
Inspecting a tune, then validating it, then rendering it currently means three separate Browse… trips to the same path. The subject bar makes those three moves one file choice and three rail clicks.

Warnings become the interface
Today a blocked RSID conversion prints two lines to a shared log box and throws a modal you have to dismiss. In the redesign the conflicts render where the decision is made, with the override checkbox directly under them — you never leave the panel to understand why nothing happened.

A render you can watch and stop
A three-minute render is currently a frozen-looking button and a log line that appears when it is over. Progress, elapsed time and a working Cancel make the longest operation in the app something you can judge and interrupt.
no feedback

The GUI teaches the CLI
Every panel carries a live sidconverter … line that rewrites itself as you touch the controls. Click through once, copy the line, and the same job is scriptable, in the flags the CLI already accepts.
two vocabularies
one, mirrored
RUN LIFECYCLE
Idle
Configured
Running
Done
Failed
Running never blocks the window. Switching rail items while a render is in flight is allowed and does not abort it; the activity strip keeps the run visible from anywhere.
Done and Failed persist. Neither is a toast. The result stays in the panel until the next run of that operation replaces it.
Failed always names a fix. Missing binary, unreadable file, blocked conversion — each carries the one command or one toggle that unblocks it.
